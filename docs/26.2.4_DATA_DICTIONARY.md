# 26.2.4 Data Dictionary

The data dictionary defines the stored fields used by the UPHSD Bookstore Point-of-Sale system. It documents each field’s meaning, Mongoose data type, required status, default, declared validation rules, and relationship to other records. It covers all 23 model-defined collections in the current source as inspected on 9 November 2026. No live database connection or record retrieval was performed.

## Dictionary conventions

- ObjectId is a BSON document identifier. Date is a stored date/time value. Number is the Mongoose numeric type; integer restrictions apply only where declared or validated by the application.
- Mixed preserves a flexible stored type. Custom validators restrict several Mixed fields, including membership, store attribution, account state, and currency markers.
- Required describes schema validation. Automatic means a field is generated or maintained by Mongoose; Conditional means the requirement depends on the record. Optional fields can still be required by a service operation.
- Defaults apply to newly created records as implemented. Computed by function indicates a function rather than a literal schema default; legacy fallback behavior is not inferred. Empty arrays can receive Mongoose array defaults.
- Dotted paths name nested fields; [] identifies an embedded array element. Embedded fields are not separate collections. __v is included only where the version key is enabled.
- Links describe schema refs or application-resolved identifiers. They are not database-enforced foreign keys. Unique constraints below are index declarations; live index installation was not verified.
- Monetary records marked moneyUnit = PHP-centavos use centavos: 100 equals PHP 1.00. Historical unmarked values and legacy financial fields require separate unit verification.
- Virtual aliases are excluded because they are not stored fields.

## Application rules that supplement field definitions

The bookstore order service requires a nonempty item list, validates positive integer quantities, reads active products within the selected store, recalculates monetary totals, and captures product snapshots. The transaction schema itself retains broader legacy payment methods and statuses; those enums do not mean every method is available in the current bookstore workflow.

Bookstore completion records a full cash or GCash payment and requires a GCash reference. The payment schema declares transactionId unique. The sale-reversal schema also declares transactionId unique, while the invoice schema does not declare one-invoice-per-transaction uniqueness.

Stock movements enforce before + delta = after and a nonzero total delta. Audit events, stock movements, bookstore command receipts, payments, and applied reversals have application middleware that rejects updates or deletion. The account password middleware hashes modified passwords and maintains security versions. These behaviors are separate from path-level required/type declarations.

Guest-order verification records link to submitted guest transactions using the same _id, as implemented by the guest-order service. The guest verification object and saved operation fingerprints are excluded from default query selection. They are not fields for public user display.

DebtPayment, InvoiceCounter, Expense, and Financial definitions remain documented because their models exist. Financial is not the authoritative source for active financial reporting. Their presence does not establish that the current bookstore interface writes all of them. No historical field values, credentials, or customer records were read to prepare this dictionary.
